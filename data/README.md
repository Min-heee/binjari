# 빈자리 데이터

가상 의원 '샘플의원'의 **합성 기존 예약**입니다. 실제 환자·병원과 관계없습니다. 이름·연락처 칸은 없고, 수술 예약에만 "의료진 A" 같은 가명 배정이 있습니다(엔진은 읽지 않음). 데이터는 AI(Claude Code)가 만들었고 **사람 검수 전**입니다.

시연 기준 시각: **2026-09-21(월) 10:00 KST**(한창구와 같음). 그 주 목~일(9/24~27)은 추석 연휴와 일요일입니다.

## 파일

| 파일 | 내용 |
|---|---|
| `bookings.json` | 기존 예약 391건(첫 상담 60, 의료진 재진 상담 93, 두피 주사 112, 두피 관리 61, 수술 후 경과 진료 49, 수술 하루 10, 수술 반나절 6)과 자원 일정 1건(9/30 의료진 1명 휴무) |
| `scripts/generate_bookings.py` | 생성기. 시드 20260921. 앱 엔진(src/core)을 쓰지 않고 볼트 json(V02·B01·B02)을 다시 읽어 따로 짠 점유 검사로 예약을 놓음 |
| `expected-slots.json` | 대조 기대값. 기준 시각 5개 × 안건 6종의 모든 시작 후보 3,580행(빈 칸 779)과 떨어진 까닭. **AI가 계산, 사람 검수 전** |
| `scripts/slots_expected.py` | 대조 계산기. 앱 코드를 쓰지 않고 볼트 json 셋과 `bookings.json`만 다시 읽어 분 단위로 검사. `src/core/expected.test.ts`가 엔진 결과와 한 행씩 비교 |

다시 만들기(저장소 루트에서): `python3 data/scripts/generate_bookings.py`, 이어서 `python3 data/scripts/slots_expected.py`. 두 번 돌려도 같은 파일이 나옵니다. 규칙(B01·V02·B02)이나 예약을 바꾸면 대조 기대값도 다시 만들어야 대조 시험이 통과합니다 — 이때 엔진과 대조가 함께 바뀌므로, 바뀐 행은 사람이 한 번 봐야 합니다.

## 모양

```
{ "meta": { ... },
  "bookings":   [{ "id": "B0001", "service": "<B01 안건 키>", "date": "YYYY-MM-DD", "start": "HH:MM",
                   "assigned": { "doctor": "의료진 A" } }],          // assigned는 수술에만, 엔진은 무시
  "exceptions": [{ "date": "YYYY-MM-DD", "resource": "<B01 자원 키>", "delta": -1, "note": "…" }] }
```

- `service`는 B01 `services`의 키입니다. `postop-visit`(수술 후 경과 진료)은 버튼으로 잡지 않고 기존 예약의 자원 점유에만 씁니다.
- 기간: 일반 예약 9/21~10/19, 수술 예약 9/21~11/2. 기준 시각을 바꿔 볼 수 있는 가장 늦은 시각(10/6 19:00) + 찾는 기간(일반 14일, 수술 28일)을 덮습니다.
- 모든 예약은 진료일에 있고, 접수 마감·진료 종료(준비 시간 포함)·점심·하루 최대·자원 수량을 지킵니다. 수술은 토요일이 아니고, 다음 날이 진료일이며, D+6~D+9에 진료일이 있습니다. 앱 시험(`src/core/data.test.ts`)이 이것을 앱 엔진으로 다시 확인합니다(예약마다 나머지 예약을 둔 채 규칙 검사).

## 만드는 규칙

1. **손으로 정한 것.** 자원 일정(9/30 의료진 −1), 수술 16건(9/28·10/1·10/12·10/14·10/23·10/27은 비움), 수술마다 D+1·D+7 경과 진료(창 안에 들어오는 것만, D+7은 V07 창 D+6~D+9 안에서 D+7 → D+8 → D+9 → D+6 순), 9/21 전 수술 4건의 D+7 경과 진료, 9/30 18:00 재진 상담 1건.
2. **무작위 채우기.** 진료일마다 안건별 목표 건수(평일·목요일·토요일을 나눔)를 시드 고정 난수로 놓습니다. 한 건 놓을 때마다 규칙을 지키는지와 **지켜야 할 칸**을 막지 않는지 보고, 어기면 버립니다.
3. **확인.** 지켜야 할 칸이 모두 비었는지, 9/30 첫 상담이 '예약 꽉 참'인지 다시 보고 어긋나면 멈춥니다.

## 심은 경계 사례와 지켜야 할 칸

PRD 7절 경계 사례 가운데 "가능"이어야 하는 칸은 합성 예약이 막지 않게 생성기가 지킵니다(`PROTECT` 목록). "불가" 사례는 규칙 자체로 불가이므로 예약과 상관없습니다.

| 칸 | 안건 | 까닭 |
|---|---|---|
| 9/21 11:00 | 첫 상담 · 주사 | 시연 첫 칸, 첫 예약 가능 시각(기준 10:00) |
| 9/21 12:00 · 9/23 14:00 · 9/28 12:00 · 10/2 10:00 | 주사 | 첫 예약 가능 시각 올림(기준 11:00 · 9/23 12:50 · 9/28 11:00 · 10/1 20:10) |
| 9/22 12:00 · 14:00 · 18:00 | 첫 상담 | 점심과 맞닿음 · 점심 직후 · 마지막 60분 칸 |
| 9/22 12:30 · 18:30 | 주사 | 점심 전에 끝남 · 접수 마감 포함 |
| 10/1 20:00 / 20:30 | 첫 상담 / 주사 | 목요일 야간 자원 · 목요일 접수 마감 |
| 10/10 14:00 / 14:30 | 첫 상담 / 주사 | 토요일(기준 10/6) |
| 9/28 · 10/1 · 10/23 10:00 | 수술 하루 | 정리 18:00~18:30 · D+1 10/2 · D+1 토요일 |
| 10/12 · 10/14 · 10/27 10:00 | 수술 하루 | 빈 수술 날(무작위 채우기가 수술 칸을 모두 먹지 않게) |
| 9/29 14:30 · 10/7 10:00 · 10/21 14:30 | 수술 반나절 | 반나절 수술 옆 칸(크기 선택이 결과를 바꾸게) |

**9/30 '예약 꽉 참'.** 의료진 2명 중 1명이 휴무이고, 남은 1명이 10:00~18:00 하루 수술에 들어갑니다. 첫 상담의 의료진 단계(시작 뒤 20~40분)가 들어갈 수 있는 칸은 18:00 하나인데, 18:00 재진 상담이 그 의료진을 18:00~18:30에 씁니다. 그래서 9/30 첫 상담은 칸 0 → "예약 꽉 참"입니다(재진 상담은 18:30 칸이 남음).

## 알아 둘 것

- 무작위 채우기는 실제 병원 예약표의 모양(수술 날을 먼저 잡고 둘레에 다른 예약을 두는 것 등)을 흉내 내지 않습니다. 빈 시간이 "드문드문"하게 보이도록 넉넉히 채웠을 뿐입니다.
- 생성기와 앱 엔진은 같은 AI가 같은 문서를 해석해 짰습니다. 구현 실수는 서로 잡지만, 해석 실수(접수 마감 포함, 점심 맞닿음)는 둘 다 같은 쪽으로 틀릴 수 있습니다.
